# Upstream research and diagnostic interface inventory

## Package contract

- NEMESIS accepts `gen5w.svm.diagnostics` under its 64-character identifier rules. Descriptor 1.1 and a single `kind=apk` application entry use the stock `pm install`, `pkg-launch` and uninstall lifecycle. The package supplies the Android package and explicit launcher component for install and removal. [NEMESIS package specification](https://github.com/xwtk/hmg_nemesis/blob/main/05-Packages.md), [NEMESIS lifecycle implementation](https://github.com/xwtk/hmg_nemesis/blob/main/NEMESIS%20Source/native/pkg.c).
- Package Manager uses Java 7 with JDK 17, Gradle 8.10.2, AGP 8.7.3 and API 19 min/target. NEMESIS and RearDashcam build their native helpers for Android ARMv7 API 19. This APK is Java-only and the installer checks for zero native library members, so it can load on that ABI without a device-specific library. [Manager build](https://github.com/hmason55/nemesis-package-manager/blob/main/docs/BUILD-AND-TEST.md), [Manager Android configuration](https://github.com/hmason55/nemesis-package-manager/blob/main/app/build.gradle), [NEMESIS native Makefile](https://github.com/xwtk/hmg_nemesis/blob/main/NEMESIS%20Source/native/Makefile), [RearDashcam build](https://github.com/KramerTech/gen5-RearDashcam/blob/main/build.sh).
- The Cloud Registry takes a direct install ZIP, requires the selected release asset and exact manifest identity, and publishes after trusted validation. A root-level USB `type` field would be rejected. The app bundle contains only the internal manifest and APK. [Release layouts](https://github.com/hmason55/nemesis-package-manager/blob/main/docs/RELEASE-LAYOUTS.md), [Registry guide](https://github.com/hmason55/nemesis-package-manager/blob/main/docs/REGISTRY-GUIDE.md), [Artifact validator](https://github.com/hmason55/nemesis-package-manager/blob/main/tools/registry_artifact.py), [Cloud validation](https://github.com/hmason55/nemesis-package-manager/blob/main/docs/CLOUD-VALIDATION.md), [Cloud deployment](https://github.com/hmason55/nemesis-package-manager/blob/main/docs/CLOUD-DEPLOYMENT.md).
- NEMESIS, HMG-API and Package Manager use AGPL-3.0. RearDashcam uses MIT. The runtime reuses no upstream source or binaries. The standard AGPL-3.0 license text is included.

## Implemented observations

| Source | What is retained | What it can establish |
| --- | --- | --- |
| Allowlisted `getprop` | Android version, incremental build, ABI, platform and hardware tokens | Reported Android build information. Confirm exact OEM SW Info separately |
| `/proc/cpuinfo`, `/proc/meminfo`, `/proc/modules` | Selected CPU fields, memory totals and relevant module names | OS-reported hardware and driver metadata |
| `/proc/pmap` | Relevant reserved region names only | A named region exists. Addresses, sizes and contents are excluded |
| `/dev`, `/sys/class/video4linux` | Matching names and access metadata | Interface presence and sampled visibility for discovered video paths |
| System/vendor library directory listings | Camera, display or GPU library filenames | Library presence |
| `service list`, `service check media.camera` | Camera-related service names and Android service registration status | Binder registration only. No method is called on a camera service |
| `logcat` | Selected camera tag, event time and fixed hint category | A matching log line existed. Camera identity, operating state and frame delivery require independent evidence |

Known relevant names include `android.hardware.RearCamera`, `com.hkmc.micom.pgs`, `/dev/admem`, `rearcamera` and VIOC. Camera tags are candidate filters based on these upstream names and the requested SVM/AVM/BVM scope. Exact OEM log tags and visibility are unverified. Permission failures and missing interfaces are recorded as capability issues. [RearDashcam technical notes](https://github.com/KramerTech/gen5-RearDashcam/blob/main/TECHNICAL.md), [RearCamera binding](https://github.com/KramerTech/gen5-RearDashcam/blob/main/src/dev/skramer/dashcam/RearCam.java), [Reserved-memory implementation](https://github.com/KramerTech/gen5-RearDashcam/blob/main/src/dev/skramer/dashcam/CameraRam.java).

## Excluded observers

RearDashcam explicitly excludes the IONIQ 5 Limited and other 360° configurations. Its recorder opens the hidden rear camera, owns the capture path, configures direct display and reads a reserved memory ring. Its overlay helper also accesses display registers. These behaviors do not establish an SVM-safe concurrent observer. The diagnostic APK does not open camera/video devices, map frame buffers or display registers, or use factory app hooks. No documented passive frame counter for the target was confirmed. `dumpsys media.camera` and undocumented vendor dumps/Binder methods are excluded because stock app permission and passive OEM behavior have not been established. [RearDashcam supported configurations](https://github.com/KramerTech/gen5-RearDashcam#rear-dashcam-for-gen5w-head-units-without-360-view), [RearDashcam ownership notes](https://github.com/KramerTech/gen5-RearDashcam/blob/main/TECHNICAL.md#reverse-and-the-camera-button), [Display helper source](https://github.com/KramerTech/gen5-RearDashcam/blob/main/native/overlay.c).

HMG-API documents a read-only `speed` value in km/h for its declared mods, backed by the telematics API. That is a potential future integration after confirming the mod contract, permissions and noninterference on this firmware. This standalone package does not require HMG-API, has no verified app-accessible speed adapter and does not invoke vehicle Binder methods. [HMG-API mod reference](https://github.com/Open-HMG/HMG-API/blob/main/docs/mod-reference.md), [Vehicle reading map](https://github.com/Open-HMG/HMG-API/blob/main/docs/micom-map.md).
